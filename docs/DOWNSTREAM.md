# Downstream evaluation suite

This document describes the fourteen benchmarks of the paper's Table 4, the scoring
protocol, how to reproduce the table, and the caveats that belong with the numbers.
Everything lives under `search_ft/downstream/`:

| file | role |
|---|---|
| `runner.py` | evaluates one checkpoint on any subset of the benchmarks, writes `downstream.json` and, optionally, per-item outcomes |
| `scoring.py` | the shared scorer (one forward pass per item), the protocol flags, sampling and few-shot helpers, the per-item log |
| `benchmarks/*.py` | one module per benchmark family; each exposes `prepare(n)` (data only) and the registered `eval_<name>` |
| `generators/` | deterministic generators of the two depth sets, PrOntoQA-Deep and Web-of-Lies-Deep |
| `prepare_data.py` | downloads or builds every benchmark's data without a model and prints the pool sizes |
| `mcnemar.py` | exact paired McNemar tests between two models' per-item files |
| `datautil.py` | data-directory, download and clone helpers |

Data goes to `$DOWNSTREAM_DATA_DIR` (or `--data-dir`; default `$GSFT_RESULTS_DIR/data/downstream`),
HuggingFace datasets to the usual `HF_HOME` / `HF_DATASETS_CACHE`. Fetch everything once on a
node with network access:

```bash
export DOWNSTREAM_DATA_DIR=/path/to/downstream_data
python -m search_ft.downstream.prepare_data
```

FOLIO is a gated dataset (`yale-nlp/FOLIO`); accept its licence on the Hub and log in once.
Footprint after `prepare_data`: about 190 MB in `$DOWNSTREAM_DATA_DIR` (ProofWriter 81 MB, only
the three `meta-test.jsonl` files are extracted from the 3.2 GB release; the PrOntoQA generator
checkout 78 MB; PrOntoQA-Deep 14 MB; LogicBench 6 MB; NLGraph 5 MB, a sparse checkout of the
test sets and k-shot prompts; Web-of-Lies-Deep 3 MB) plus about 750 MB of HuggingFace caches,
most of it the 70,631-row CLUTRR dump.

## The fourteen benchmarks

Every benchmark except NLGraph is scored by log-likelihood over a fixed label set, with one
forward pass per item. The metric is pooled accuracy, the fraction of all scored items answered
correctly; `n` is the number of scored items in the paper, and it is the default when `--n` is
omitted. The few-shot demos are never scored.

| registry name | Table 4 row | shots | n | strata | data (fetched on first use) |
|---|---|---|---|---|---|
| `proofwriter` | ProofWriter OWA | 0 | 3000, class-balanced per depth | QDep 0 to 5 | AllenAI `proofwriter-dataset-V2020.12.3.zip`, OWA/depth-5/meta-test |
| `proofwriter_cwa` | ProofWriter CWA | 0 | 3000 | QDep 0 to 5 | same zip, CWA/depth-5/meta-test |
| `pararules` | ParaRules | 0 | 4566 (whole balanced pool) | QDep 0, 1, 2, 3 to 5 | same zip, OWA/NatLang/meta-test (human-paraphrased rules) |
| `zebra_mc` | ZebraLogic-MC | 3 | 1000 | 25 grid sizes | HF `WildEval/ZebraLogic`, config `mc_mode`, split test |
| `prontoqa_deep` | PrOntoQA-Deep | 8 | 4000, k in {1,2,4,8,16,32,48,64} | 8 depths | generated by `generators/prontoqa_deep.py` from the official `asaparov/prontoqa` generator |
| `folio` | FOLIO | 8 | 203 (whole validation split) | none | HF `yale-nlp/FOLIO` (gated), demos from its train split |
| `justlogic` | JustLogic | 3 | 4897 (whole set minus demos) | depth 1 to 7 | HF `michaelchenkj/JustLogic` |
| `proverqa` | ProverQA | 3 | 1497 (whole dev set minus demos) | easy, medium, hard | HF `opendatalab/ProverQA`, `dev/{easy,medium,hard}.json` |
| `clutrr` | CLUTRR | 5 | 1000, k = 2 to 10 | 9 hop counts | HF `kendrivp/CLUTRR_v1_extracted`, `task_split == test`, clean `task_1` family; demos from `task_split == train` |
| `logicbench_bqa` | LogicBench-BQA | 3 | 1512 (whole eval set minus demo contexts) | none | `github.com/Mihir3009/LogicBench`, LogicBench(Eval)/BQA |
| `ruletaker` | RuleTaker | 5 | 1000 | the five base partitions depth-0, -1, -2, -3, -5 | HF `tasksource/ruletaker`, split test |
| `web_of_lies_deep` | Web of Lies | 3 | 4000, k in {1,2,4,8,16,32,48,64} | 8 depths | generated by `generators/web_of_lies_deep.py` (seed 42, 65-name pool) |
| `logiqa` | LogiQA | 3 | 648 (whole test set minus demos) | none | HF `hails/agieval-logiqa-en`, split test |
| `nlgraph` | NLGraph | 4 (the benchmark's own `k-shot-prompt.txt`) | 1000 (all test items), generation-scored | 8 tasks | `github.com/Arthur-Heng/NLGraph`, `<task>/test.json` |

Labels: True/False/Unknown for ProofWriter OWA and ParaRules, True/False for ProofWriter CWA,
RuleTaker and PrOntoQA-Deep, True/False/Uncertain for FOLIO and JustLogic, A/B/C for ProverQA
(the options are always A) True, B) False, C) Uncertain), A/B/C/D for LogiQA, Yes/No for Web of
Lies, yes/no for LogicBench-BQA (the case its prompt asks for), the 18 kinship relations that
occur as gold for CLUTRR, and each puzzle's own choice list for ZebraLogic-MC. NLGraph is scored
on generated text (200 new tokens) with a port of the benchmark's per-task scorers; its GNN task
gives per-node partial credit, every other task is 0 or 1.

Few-shot construction: PrOntoQA-Deep uses a fixed 8-item block at k=2 (4 True, 4 False, no chain
of thought); Web of Lies uses the three canonical BBH exemplars verbatim; FOLIO takes the first
eight train items covering all three labels; ZebraLogic takes three small puzzles (2x2, 2x3) with
distinct answers; JustLogic and ProverQA take one demo per label from depth 1 and from `easy`;
LogicBench takes one demo per context with alternating yes/no labels and removes every question
on those contexts; CLUTRR, RuleTaker and LogiQA draw seeded, label-balanced demos (round-robin
over gold values) and remove them, RuleTaker removing every question on a demo's theory. All
seeds are fixed in the code, so the scored item sets are identical across models, which is what
the paired tests need.

Generated depth sets: `prepare_data` (or the first evaluation) clones the official PrOntoQA
generator at commit `0a6412b6` and builds `prontoqa_deep.jsonl` (seed 1000 + k per depth, the
(query polarity x label) 2x2 balanced at 125 per cell per depth, every item parse-verified by the
official code and re-derived from its first-order formulas) and `web_of_lies_deep.jsonl` (Yes/No
exactly 250/250 at every depth, every item re-parsed and re-solved). Both builds are
deterministic; the files used for the paper are reproduced byte for byte.

## Scoring protocol

The runner's flags default to the paper's final protocol.

| flag | default | meaning |
|---|---|---|
| `--answer-cue` | `assistant` | Chat mode only. A trailing cue in the prompt (`Answer:`, `A:`, `the answer is`, LogiQA's `A: Among A through D, the answer is`) is moved out of the user turn and prefilled at the start of the assistant turn, so a label is the model's natural next token. `user` leaves the whole prompt in the user turn. |
| `--label-variant` | `auto` | Which surface form of each label is scored. At a chat turn boundary the next token is the bare label (`Yes`, Qwen3 id 9454); after a prefilled cue, or in completion mode, it carries the space (` Yes`, id 7414). `auto` picks the form the model emits at the scored position; `space`, `bare` and `max` are the fixed alternatives. Scoring only the space form under a chat template read tokens about 10 nats below the real candidates. |
| `--length-norm` | `off` | `on` or `auto` divide a label's summed log-probability by its UTF-8 byte length (lm-eval `acc_norm`). Off in the paper: it is a fixed per-label rescaling that favours long labels. |
| `--cue-suffix` | `""` | Text prefilled after the cue in chat mode. `"**"` is needed for untrained Qwen3 chat models, which answer in markdown bold (`Answer: **True**`); see the caveats. |
| `--chat-template` | `auto` | Use the tokenizer's chat template if it has one (Qwen3 yes, Pythia no). |
| `--gen-max-new-tokens` | `200` | Generation budget of NLGraph. |

Each label is also scored in its lower-case and capitalised spellings and the best is kept
(the prompt decides whether the model writes ` true` or ` True`); single letters keep their
exact case and are also scored in the parenthesised form `(B`. Besides the reported
log-likelihood accuracy, every stratum records the greedy accuracy (the model's actual top-1
token mapped to a label, with one constrained second step for labels that share a first token
such as `father` and `father-in-law`), the calibrated accuracy (per-label log-probabilities on a
content-free prompt subtracted first), the majority-class rate and per-class accuracy. The greedy
column is the label-emission diagnostic: a model that starts prose instead of answering scores
near zero there, and its log-likelihood column then reads a position the model does not use.

## Reproducing Table 4

Table 4 compares the stage-48 checkpoint of the curriculum run against the final checkpoint of
the run trained at a fixed L=48 without a curriculum, at matched compute. With the configs of
this repository the curriculum run writes its stage checkpoints to
`$GSFT_RESULTS_DIR/runs/<curr_run>/stage_checkpoints/stage_48_step_<step>_L48`.

```bash
export DOWNSTREAM_DATA_DIR=/path/to/downstream_data
BENCH="proofwriter proofwriter_cwa pararules zebra_mc prontoqa_deep folio justlogic proverqa \
       clutrr logicbench_bqa ruletaker web_of_lies_deep logiqa nlgraph"

python -m search_ft.downstream.runner \
    --checkpoint $GSFT_RESULTS_DIR/runs/<curr_run>/stage_checkpoints/stage_48_step_<step>_L48 \
    --run_name curr48 --benchmarks $BENCH --items-output items_curr48.json
python -m search_ft.downstream.runner \
    --checkpoint $GSFT_RESULTS_DIR/runs/<nocurr_run>/checkpoint-<final> \
    --run_name nocurr48 --benchmarks $BENCH --items-output items_nocurr48.json

python -m search_ft.downstream.mcnemar --a items_curr48.json --b items_nocurr48.json
```

Without `--n` every benchmark runs at the sample size of the table; `--n` spreads a smaller cap
over the strata for a quick check. The runner writes `downstream.json` (per-stratum and overall
metrics, the protocol used, the data directory) and the items file
`{run_name: {benchmark: [{item_id, subset, gold, pred, correct, metric}]}}`. `mcnemar.py` pairs
the two files by item id (the sets must match exactly) and prints, per benchmark, the discordant
counts, both accuracies, the difference with a bootstrap interval, the exact two-sided McNemar p,
the mid-p and the naive two-proportion z-test p for comparison.

Values of the paper (Qwen3-1.7B, bf16, paired re-run on H100; curr48 is 137.1K PFLOPs, nocurr48
128.4K):

| benchmark | curr48 | nocurr48 | delta | McNemar p |
|---|---|---|---|---|
| ProofWriter OWA | 54.9 | 40.6 | +14.3 | 5e-47 |
| ProofWriter CWA | 67.9 | 55.2 | +12.8 | 3e-30 |
| ParaRules | 55.1 | 50.4 | +4.7 | 7e-14 |
| ZebraLogic-MC | 53.5 | 48.3 | +5.2 | 2e-4 |
| PrOntoQA-Deep | 57.1 | 52.0 | +5.1 | 3e-10 |
| FOLIO | 45.8 | 41.4 | +4.4 | 0.023 |
| JustLogic | 53.5 | 46.1 | +7.4 | 1e-22 |
| ProverQA | 47.8 | 49.2 | -1.4 | 0.27 |
| CLUTRR | 28.6 | 26.7 | +1.9 | 0.13 |
| LogicBench-BQA | 73.6 | 71.2 | +2.4 | 0.027 |
| RuleTaker | 60.0 | 58.8 | +1.2 | 0.38 |
| Web of Lies | 57.9 | 57.8 | +0.2 | 0.84 |
| LogiQA | 42.4 | 43.4 | -0.9 | 0.64 |
| NLGraph | 43.7 | 46.2 | -2.5 | 0.012 |

Near-tie items can flip between GPU types and kernels (0 to 14 items per arm between L40S and
H100 in the paper's runs), so expect agreement to within a few tenths of a point, not to the item.

## Known caveats

**NLGraph is a significant loss for the curriculum.** The paired test on 0/1 correctness gives
curr48 43.7 against nocurr48 46.2, p = 0.012; the unpaired z-test (p = 0.26) hides it. The
reported mean score credits GNN per node, which moves the number by about 0.1 point relative to
the 0/1 outcomes the test uses. The result is disclosed with the table and is not a scoring
defect: label emission is 100% on every trained arm.

**ProofWriter OWA and ParaRules are class-balanced within each depth.** In the raw OWA data the
Unknown share falls from 69% at QDep 0 to 3% at QDep 5, because unprovable questions carry the
depth of the deepest failing proof search. A constant-Unknown predictor would therefore score
66/54/34/22/7/4 by depth, and a per-depth curve on the raw mix is the class prior. Each depth
stratum is sampled with equal True/False/Unknown counts (the Unknown count at QDep 5 is 63, so
that stratum holds 189 items), which makes the reported number the balanced accuracy at that
depth with chance 33.3% everywhere. CWA is two-way and balanced by construction (majority never
above 53%) and is not resampled. ParaRules merges QDep 3 to 5 because Unknown is rare past depth
2 (72 / 6 / 1 items at QDep 3 / 4 / 5).

**Untrained Qwen3 chat models need `--cue-suffix "**"`.** The base Qwen3-1.7B answers after the
prefilled cue in markdown bold (` **True**`, ` **B**`) and starts a step-by-step essay on the
cue-less zero-shot ProofWriter prompts, so under the default protocol its greedy label emission is
0 to 2% and its log-likelihood column reads a position it never uses (the paper's first base-model
numbers were discarded for this reason). With `--cue-suffix "**"` the scored prefix is
`Answer: **` plus the bare label, or `**Answer:` plus the space-prefixed label where the prompt
has no cue, and the greedy output equals the scored label on every benchmark. NLGraph then
prefills the prompt's own `A: **` in the assistant turn and strips asterisks before scoring. The
trained arms answer plainly and are scored with the empty suffix; only CLUTRR and LogicBench-BQA
have the untrained model emitting labels without the suffix.

**Compute gap.** nocurr48 is at 128.4K PFLOPs against curr48's 137.1K, 6.3% short, so every delta
is flattered by that margin. The extra compute would go to the no-curriculum arm, so the residual
runs against the curriculum claim. Disclosed in the table caption rather than closed.

**LogicBench-BQA carries a 65.8% majority class.** Both arms beat it, but curr48 answers No
correctly 91.5% of the time and Yes 38.7%, while nocurr48 is at 78.0 and 58.6. On label-wise
accuracy, which is what Parmar et al. report, the ordering reverses (65.1 against 68.3), so part of
the +2.4 is the class prior. The runner reports `acc_yes`, `acc_no`, `balanced_accuracy` and
`majority_baseline` beside the pooled number.

**Web of Lies admits a surface shortcut and saturates.** The answer is the parity of the word
"lies" with the root folded in (500 of 500 items at every depth), inherited from BBH's task
design. Every arm is at 86 to 96 at one hop and at chance from four hops on.

**PrOntoQA-Deep is label accuracy without a proof.** PrOntoQA's own protocol scores a generated
proof; the no-chain-of-thought framing used here rules that out, and the dataset's authors
caution that label accuracy alone is a weak reasoning measure. Demos are fixed at k=2 as in the
PrOntoQA-OOD depth-generalisation design. The `polarity_baseline` field (the rule "query says 'is
not', so False") is 50% at every depth by construction.

**RuleTaker strata are partitions.** They are the theory's maximum depth, not the per-question
inference depth, which the HuggingFace mirror does not carry; a depth-N stratum contains
questions of every depth up to N. The depth-3ext and NatLang configs are excluded (supersets of
the base partitions, and the paper's separate transfer test).

**CLUTRR is scored on a 1,000-item cap** spread over k = 2 to 10 (the clean test pool holds 2,641
items), so a run with a different cap scores a different item set and cannot be paired with the
paper's files.

**Dropped from the release** because they are not in Table 4: Multi-LogiEval (5 of 15 strata
have no label variance), StepGame and StepGame-Deep (every arm at or below the majority rate),
PrOntoQA-OOD (proofs-only data, no True/False label exists), LogicBench-MCQA (superseded by BQA),
the BBH tasks (null or floored, including a first pass with non-canonical demos that is invalid),
and the zero-shot variants of CLUTRR, LogiQA, RuleTaker and ZebraLogic (superseded by the
few-shot rows under the uniform rule).
